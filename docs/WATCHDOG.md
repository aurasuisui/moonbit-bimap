# 无人看守 · 自动进度检查 + 自动续跑(看门狗)

> **原理**:Claude 会话只有在"空闲"时才会被定时任务唤醒。所以做法是——在**执行会话里**
> 建一个**周期性 cron 任务**:每当会话空闲(比如它误以为做完了、或在等输入),cron 就自动
> 把一段"检查进度、补齐未完成项"的提示词喂回去,让它**自己审计、自己续跑**,不需要人。
>
> **关键**:这个 cron 必须建在**执行会话内部**(执行会话自己调 `CronCreate`),而不是别处——
> 因为定时任务只能唤醒它所在的那个会话。所以下面第 1 步是让执行会话自己建任务。

---

## 怎么用(两步)

### 第 1 步:在执行会话里,粘完 `START_PROMPT.md` 的内容后,**紧接着再粘这段**,让它给自己装上"心跳":

```
另外:为确保无人看守下不会半途停下,请你现在用 CronCreate 给自己建一个周期性自检任务,
然后立即开始执行 START_PROMPT 的任务。建任务的参数如下:

CronCreate({
  cron: "17,47 * * * *",        // 每小时的 :17 和 :47 各触发一次(避开整点高峰)
  recurring: true,
  prompt: "<把下面【看门狗提示词】那一整段原样粘在这里>"
})

建好后不要等它,马上开始干活。之后每当你空闲,这个任务会自动唤醒你自检续跑。
```

### 第 2 步:把【看门狗提示词】(下面框内整段)填进上面的 `prompt` 字段。

---

## 【看门狗提示词】(周期触发时自动执行)

```
【自动进度自检 · 无人看守续跑】这不是新任务,是周期性心跳。请按以下步骤自检并续跑 moonbit-bimap:

1. 读 docs/EXECUTION.md(里程碑定义)和 docs/EXECUTION_REPORT.md(若已存在)。
2. 用 git log、ls、以及 `moon check` / `moon test` 判断当前真实进度:
   - 哪些里程碑(M0–M5)已真正完成(代码在、测试绿、已提交)?
   - 五步 CI 是否全绿?`moon info` 后 `git diff --exit-code` 是否干净?
   - 测试数是否 ≥200?是否已发布 mooncakes.io(或留了 PUBLISH.md)?
3. 找出第一个"未完成"的事项,立即继续实现它(遵循 START_PROMPT 的大方向与 SPEC.md)。
   不要等待任何确认——无人看守,自己拍板,继续往前推进。
4. 卡住就按 EXECUTION.md §5 绕过(ignore 测试 / 砍范围 / 记 Known Issues),绝不停摆。
5. 每完成一个里程碑就 `git commit`(Conventional Commits)。
6. 只有当【完成定义】全部满足时,才写/更新 docs/EXECUTION_REPORT.md 并声明完工;
   在那之前,每次被唤醒都要继续干活,不要只汇报不动手。

现在开始自检并续跑。
```

---

## 说明 / 注意

- **cron 只在会话存活期间有效**,且**只在会话空闲时触发**。所以它的作用是:一旦执行会话
  误以为做完而 idle,心跳会把它叫醒继续干——正好补上"无人看守别停下"的诉求。
- 周期任务**最长存活 7 天后自动过期**;6 小时任务绰绰有余。
- 想停掉:在该会话里说"删掉自检 cron"即可(它会调 `CronList` + `CronDelete`)。
- 频率 `17,47 * * * *` = 每小时两次。想更密(每 ~20 分钟)可改 `7,27,47 * * * *`。
- **更稳的兜底**:执行会话若被设计成"做完一段就主动 ScheduleWakeup 排下一次"(动态自我 pacing),
  比 cron 更贴。可在 START_PROMPT 里加一句"每完成一个里程碑,用 ScheduleWakeup 排 90s 后
  自检续跑",形成自我驱动闭环。需要的话我可以把这句加进 START_PROMPT。
