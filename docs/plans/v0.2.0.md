## 1. `retain`(BiMap)——**移植项**

> 真源:bimap-rs 0.6.3 的 `BiHashMap::retain`(hash.rs:624)与 `BiBTreeMap::retain`
> (btree.rs:378)均存在,谓词 `FnMut(&L, &R) -> bool`;crate 自带 `retain_calls_f_once`
> 测试。本方案的"恰好求值一次"语义与真源吻合。**retain 是移植,不是原创。**

### 签名
```moonbit
pub fn[L : Hash + Eq, R : Hash + Eq] BiMap::retain(
  self : BiMap[L, R], f : (L, R) -> Bool,
) -> Unit
```
保留 `f(l, r) == true` 的对,其余删除。

### 语义
- 谓词对每对**恰好求值一次**,按插入序求值(基于 `into_array()` 快照)——对齐
  crate 的 `retain_calls_f_once`。
- **保留相对插入顺序**(剩余对的先后关系不变)——保序是本库卖点,retain 必须守。
- 全部保留时是 no-op:**不 bump version**(迭代器不失效,可测试观测)。
- 文档声明:谓词内不得改 map(快照求值;违规修改不会被吞,但语义不做承诺)。

### 实现(O(n) 三遍扫描,不踩 O(n²) 头删坑)
不走"逐个 remove_by_left"(会触发 order 移位二次复杂度):
1. 快照 + 过滤出 `removed_lefts`(谓词恰好一次);空则直接返回(不 bump)。
2. 对每个 removed left:`forward.remove` 取回右值 → `backward.remove` →
   `positions.remove`。
3. **原地压实 `order`**:写指针扫描,`positions.contains(l)` 判留(此时 positions
   恰含保留键),**同步 `positions[l] = w`**;尾部 pop 截断。
4. `len -= removed.length(); version += 1`。

不重分配字段(守"字段永不重赋值"纪律),不需要 HashTab::clear。

### 纪律登记(核验修正 a)
retain 是**绕过 remove_by_left/right 的第三个 mutation 收口点**(批量删除路径:
逐对三表删除 + order 原地压实)。必须:
- `src/bimap.mbt` 文件头 chokepoint 注释更新;
- CLAUDE.md / AGENTS.md / CONTRIBUTING.md 纪律段显式登记;
- `bimap_wbtest.mbt` 增加 retain 后的强不变量断言(五计数、positions/order 自洽、
  双表互逆)。

### 差分路径(核验修正 b)
- **M1**:model_test.mbt oracle 加 `oracle_retain`,且 LCG 流 op 集从 4 扩为 5
  (`op = state % 5`,op 4 = retain,谓词用确定函数 `(l + r) % 3 != 0`)。
- **M3**:diffgen 同步镜像该 5-op 流(同一谓词),retain 进真源差分。
- 流定义只在 model_test 与 diffgen 两处,必须逐字一致。

### 测试(~9 + 属性 + wbtest)
保留子集/顺序保持/全保留 no-op(**迭代器仍可用**=未 bump version 的可观测证明)/
全删/空表/谓词恰好一次(Array 计数器)/C4 态上 retain/属性测试(过滤后与 oracle
对拍 + 不变量)/wbtest 强不变量。

## 2. 集合视图 + entry 风格助手——**原创扩展**

> 真源核验:`get_or_insert_left/right` 在 bimap-rs 0.6.3 **不存在**——这两个是
> **原创扩展而非移植**(与保序/索引同级),无真源可差分;SPEC/README 定位写明
> "原创",测试必须自带完整语义钉死。

### 设计决策:不做活视图
MoonBit 无 Set trait,Guava 式活视图也无所有权基础——与 `to_inverse` 选拷贝同一理由。
**做快照访问器 + 成员判定 + 安全 entry 助手**,不做视图对象。

### 新增 API(BiMap,BiBTreeMap 提供同形并行版)
```moonbit
// 成员
pub fn[L : Hash + Eq, R : Eq] BiMap::contains_pair(self, l : L, r : R) -> Bool
    // forward.get(l) == Some(r),即 C1 判定;O(1)

// 快照(插入序)
pub fn[L, R] BiMap::left_keys(self) -> Array[L]          // order 的拷贝,零约束
pub fn[L : Hash + Eq, R] BiMap::right_values(self) -> Array[R]

// entry 风格助手(最小集,原创)
pub fn[L : Hash + Eq, R : Hash + Eq] BiMap::get_or_insert_left(self, l : L, r : R) -> R
pub fn[L : Hash + Eq, R : Hash + Eq] BiMap::get_or_insert_right(self, r : R, l : L) -> L
```

### `left_keys` 与既有 `lefts()` 的定位差异(写进 SPEC)
`lefts()` 是迭代器且要 `L : Hash + Eq`;`left_keys()` 的增量是**零约束 + 直出
Array**——这是它存在的理由,不是重复建设。

### `get_or_insert_*` 文档块的惊奇面(核验要求)
> 调用返回后 `l ↔ r` 保证成立;但 `r` 原先绑定的对可能被 C3 驱逐
> (完整 insert 语义,非"仅当空闲才插入")。

### 与 SPEC §10 的冲突裁决
SPEC §10 排除的是 **OccupiedEntry/VacantEntry 视图对象、get_mut、update 类回调修改**
(indexmap 的历史 bug 聚集地:entry 缓存索引在结构变更后失效)。本方案**不引入任何
entry 对象与 update 回调**——`get_or_insert_*` 是无状态的一次性查询-插入组合,全部
走既有 `insert` 路径,不产生 SPEC §10 所列失效风险面。SPEC §10 补一句裁决说明。

### 测试(~10)
contains_pair 的 C0/C1/半存在态;left_keys/right_values 与 into_array 一致性 + 空表 +
零约束可用性;get_or_insert 的已存在/不存在/**C3 夺取路径** ×左右对称(语义钉死)。

## 3. `BiBTreeMap`(排序双射)——v0.2.0 主体工程

### 引擎决策:core `SortedMap`(实测确认)
get/set/remove/contains/iter/keys/values/range/to_array/length/copy 齐全,键约束
`Compare`。**注意:`set` 返回 Unit(不还旧值)**——插入语义必须"get 预判 + set",
这是实现上的唯一正路。不自研平衡树(省 ~800 行 + 测试面)。core 是标准库,零依赖
声明不受影响(与 positions 用内置 Map 同理)。

### 约束定案(核验):`Compare` 蕴含 `Eq`
`builtin/traits.mbt:34` 实测 `pub(open) trait Compare: Eq`(超类关系)。故约束直接写
**`L : Compare, R : Compare`**,C1 判定的 `==` 免费可用。**trait impl 约束逐个
最小化**(0053 教训,mbti 门禁盯着):例如反查类方法只需 `R : Compare` 一侧。

### 数据布局
```
BiBTreeMap[L, R]                    // L : Compare, R : Compare
├── forward  : SortedMap[L, R]      // 按 L 有序
├── backward : SortedMap[R, L]      // 按 R 有序(反查)
├── len      : Int   (mut)
└── version  : Int   (mut)          // fail-fast 迭代(与 BiMap 同构)
```
**没有** order/positions:排序取代插入序,索引访问不提供(SPEC §11 与 BiMap 差异表
明示,不是遗漏)。

### API(镜像 BiMap,去掉顺序/索引,加排序红利)
```moonbit
// 构造/转换
new(), from_array(pairs)   // 后赢,同 BiMap/Rust FromIterator
copy(), to_inverse()       // 拷贝,同 BiMap 决策

// 插入(复用 lib.mbt 的 Overwritten 枚举——真源确认 btree.rs 同款)
insert(l, r) -> Overwritten[L, R]          // C0–C4 语义与 BiMap 完全一致
insert_no_overwrite(l, r) -> Result[Unit, (L, R)]   // 真源 btree.rs:479 同款

// 查找/删除
get_by_left / get_by_right / contains_left / contains_right
remove_by_left(l) -> R? / remove_by_right(r) -> L?

// 查询
len(), is_empty()
first() -> (L, R)?    // 最小左键(排序红利)
last()  -> (L, R)?    // 最大左键
range(lo : L, hi : L) -> Iter[(L, R)]   // ★ 显式决策,见下

// v0.2.0 新 API 并行版
retain(f)(真源 btree.rs:378 同款), contains_pair, left_keys(排序), right_values
get_or_insert_left/right(原创)

// 迭代
iter() -> Iter[(L, R)]        // 按 L 升序(fail-fast)
into_array() -> Array[(L, R)] // 按 L 升序

// traits(全套对齐,约束逐个最小化)
Debug / Default / Show / ToJson / Eq / Hash / Arbitrary
```

### range 显式决策(核验要求:做或明确 defer,不得无意识遗漏)
- **做**:`range(lo, hi) -> Iter[(L, R)]`,按左键的正向区间迭代。排序结构三大红利
  (有序迭代 / first-last / 区间查询)只给前两个太亏;core `SortedMap::range` 现成,
  包装成本 ~30 行。边界语义**以 core SortedMap::range 实测为准**(实现时确认含/不含
  端点),SPEC §11 与 doc 块写明。真源参考:bimap-rs `left_range`(btree.rs:521)。
- **defer**:按右键的反向区间迭代(Rust `right_range`,btree.rs:558)。理由:反向查找
  已有 `get_by_right` 覆盖主需求;反向区间无真源差分以外的紧迫场景,留 v0.2.x 按反馈
  增补。SPEC §11 明确记录此 defer。

### 语义要点
- **Eq**:对集合相等(与 BiMap 同语义)。
- **Hash**:复用 `pair_fingerprint` + sort-fold 组合器(同 pair 集合 hash 一致)。
- **不变量纪律照搬**:双表互逆 + 计数一致;变更走私有收口 helper(SortedMap 原语上
  实现,get 预判 + set);retain 为批量收口点(同 BiMap 纪律)。
- **first/last 语义与 BiMap 不同**:BiMap = 最早/最晚插入,BiBTreeMap = 最小/最大键。
  SPEC §11 差异表显式对比,防迁移误用。
- fail-fast abort 同 BiMap:不可进程内测试,文档化。

### 差分测试升级:真源扩展到 BiBTreeMap
bimap-rs v0.6.3 自带 BiBTreeMap(默认 feature)。扩展 `tools/diffgen`:第二份夹具,
**5-op LCG 流**(含 retain,谓词与 model_test 逐字一致)+ 黄金序列,并**加测排序终态**
(迭代序与 Rust 端一致,全量比对——比 BiMap 的成员判定更强)。
MoonBit 侧:`src/bbtreemap_diff_test.mbt`。

### 文件布局
```
src/bbtreemap.mbt           # 核心:双 SortedMap + 收口 helper
src/bbtreemap_traits.mbt    # traits 全套
src/bbtreemap_test.mbt      # C0–C4、排序迭代、删除、first/last/range/retain
src/bbtreemap_diff_test.mbt # 对 Rust BiBTreeMap 差分
src/bbtreemap_diff_fixture_test.mbt  # diffgen 生成
docs/SPEC.md                # 新增 §11 BiBTreeMap 章(含差异表 + range 决策 + defer 记录)
```

### 测试规模估计
~48 个:C0–C4 矩阵、排序序断言、range 边界、删除对称、first/last、retain、traits、
差分(黄金+6000 步+排序终态)、属性不变量。
