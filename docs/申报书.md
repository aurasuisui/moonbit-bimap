## 项目简介

MoonBit BiMap 计划将 Rust 生态中广泛使用的 `bimap` crate(双向映射/双射容器)移植到
MoonBit 生态,并额外提供 **保持插入顺序** 与 **按位置索引访问** 两项原库不具备的能力,
为 MoonBit 开发者提供一个键与值一一对应、既可正向(键→值)也可反向(值→键)查找的映射实现。

双向映射在工程中用途广泛:用户名↔邮箱、国家名↔国家码、枚举值↔序列号、实体 ID↔句柄等
天然一一对应的场景,都需要"正反都能查、且两侧都唯一"的容器。MoonBit 内置 `Map[K, V]`
只支持单向查找,且值可重复;`moonbit-bimap` 正是填补这一空白的标准方案。

项目面向所有 MoonBit 应用开发者、库作者与工具链开发者。它与作者已完成的同生态项目
`aurasuisui/indexmap`(保序哈希表)组成"有序集合家族":**indexmap 解决"按位置访问保序映射",
bimap 解决"双向一一对应"**,两者解决的是正交问题,共享底层哈希表工程。

## 核心功能范围

- 提供 `BiMap[L, R]` 数据结构,保证键与值一一对应(双射),支持正向 `get_by_left` 与反向 `get_by_right` 查找;
- 采用两张互逆的 Robin Hood 开放寻址哈希表(左→右、右→左),保证 O(1) 平均查找;
- 提供对齐 Rust `bimap` 的插入语义:`insert` 返回 `Overwritten` 枚举(`Neither`/`Left`/`Right`/`Both`/`Pair`,覆盖 C0–C4 五情形,含 C4"两对塌缩、len 净减 1"的经典陷阱);`insert_no_overwrite` 返回 `Result[Unit, (L, R)]`;
- 通过附属 `order: Array[L]` 与 `positions: Map[L, Int]` **保持左键插入顺序**,迭代严格按插入顺序输出(原库不具备);
- 支持按插入位置索引访问 `get_index`、`get_index_of_left`、`get_index_of_right`、`first`、`last`(原库不具备);
- 提供对称的删除 `remove_by_left` / `remove_by_right`,自动双侧清理以维护双射不变量;
- 提供反向副本 `to_inverse() -> BiMap[R, L]`(拷贝,非实时活视图);
- 实现 `Debug`、`Default`、`Show`、`ToJson`、QuickCheck `Arbitrary` 标准 trait;`Eq` / `Hash` 采用**顺序无关**语义(双射即"对的集合");
- 提供 fail-fast 迭代器(`iter` / `lefts` / `rights` / `into_array`);
- 提供不少于 200 个测试用例,含覆盖核心不变量("两表互逆 + 五处计数一致")的 QuickCheck 属性测试、C0–C4 × 插入语义矩阵、删除对称性、扩容级联与 1 万级压力测试;
- 提供 README、CONTRIBUTING(架构深度解析)、CHANGELOG 与可运行示例(`cmd/`);
- 使用 GitHub Actions 持续集成,覆盖格式化检查、类型检查、接口同步检查、测试与编译流程。

## 移植或参考说明

- **原项目名称**:bimap(另概念参考 Guava `BiMap`)
- **原项目链接**:https://github.com/billyrieger/bimap-rs ;https://github.com/google/guava
- **原项目许可证**:bimap-rs 为 Apache-2.0 OR MIT;Guava 为 Apache-2.0
- **本项目许可证**:Apache-2.0

与原项目相比,本项目做了以下适配、简化与增强:

- 使用 MoonBit 原生 `struct`、`trait`(`Hash + Eq`)、`enum`、`Array` 与测试体系组织代码,不照搬 Rust 的类型系统与模块结构;
- 哈希表采用 Robin Hood 开放寻址,**改编自作者本人的 `aurasuisui/indexmap`(Apache-2.0)**,不依赖 MoonBit 内置 Map 的不稳定 API,确保自包含与长期可维护;
- 用 MoonBit 的 `enum Overwritten[L, R]` 表达插入返回的 5 种情形,充分利用 MoonBit 的代数数据类型(对应 Rust 的 `Overwritten` 枚举);
- 底层为两张独立的 Robin Hood 表,不实现 Rust 默认依赖 `std::HashMap` 的可插拔哈希(`HashBuilder`),直接使用 MoonBit 内置 `Hash` trait;
- **增强(原库不具备)**:新增保持插入顺序与按位置索引访问能力,通过 `order` + `positions` 实现;
- **简化**:`to_inverse()` 采用拷贝而非 Guava 的实时活视图,以契合 MoonBit 的所有权模型;`Eq`/`Hash` 采用顺序无关语义(与 Rust `bimap` 的 `PartialEq` 一致);
- **暂不移植**:`BiBTreeMap`(有序变体)、serde 集成,列为后续 v0.2.0 扩展范围。

## 与原参赛项目(moonbit-indexmap)的实质性区别

> 黑客松规则:黑客松项目须与原参赛项目存在实质性区别。本项目与 `moonbit-indexmap` 的差异如下:

| 维度 | moonbit-indexmap | **moonbit-bimap** |
|---|---|---|
| 解决的问题 | 保序 + **按位置**访问 | **双向一一对应(双射)** + 反查 |
| 值的唯一性 | 值可重复 | **值也唯一(双射约束)** |
| 反向查找(值→键) | ❌ 无 | ✅ 核心能力 |
| 核心不变量 | 插入序 + 索引映射 | **两表严格互逆 + 五处计数一致** |
| 插入语义 | `insert` 覆盖单值 | **C0–C4 五情形 / `Overwritten` 枚举**(含 C4 塌缩、len 净减 1) |
| `Eq` / `Hash` | **顺序敏感** | **顺序无关**(双射=对的集合) |
| 数据结构 | 单张 Robin Hood 表 + order | **两张互逆 Robin Hood 表 + 一份 order** |

两者共享的仅是底层哈希表这一工程组件(如同任何两个映射库都使用数组);
**数据结构语义、核心不变量、插入语义、Eq/Hash 语义完全不同。本项目是对成熟开源库
(Rust `bimap`)的移植与增强,非 indexmap 的拆分、改名或简单修改。**
